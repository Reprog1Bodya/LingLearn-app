# LingLearn — Мобильное приложение для изучения иностранных языков

Полнофункциональное кроссплатформенное мобильное приложение на **Godot Engine 4** (GDScript) с серверным бэкендом на **FastAPI**, **SQLAlchemy 2.0 ORM**, **Alembic** и **PostgreSQL**.

Проект ориентирован на требования документов **Vision**, **SAD** и критерии **всех 6 кейсов** (включая требования со звёздочкой `*`). Документы лежат в `docs/`.

---

## Быстрый старт

### 1. Сервер — вариант A: одной командой через Docker (рекомендуется)

```bash
cp .env.example .env        # задайте POSTGRES_PASSWORD, SECRET_KEY (>=32 символов), ADMIN_PASSWORD
docker compose up --build   # PostgreSQL + API; миграции Alembic применяются автоматически
```

Никаких venv, версий Python и пакетов на компьютере не нужно.

### 1. Сервер — вариант B: локально (Python 3.10–3.13)

```bash
docker compose up -d db                 # PostgreSQL (или свой, тогда поправьте DATABASE_URL)
cd server
python3 -m venv venv && source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                    # задайте SECRET_KEY (>=32 символов) и ADMIN_PASSWORD
python server.py                        # применит миграции, запустит API и запишет адрес в client/server.cfg
```

* **Адрес API:** `http://<IP компьютера>:8080` (его печатает `server.py`)
* **Swagger UI:** `/docs`, **ReDoc:** `/redoc`, **OpenAPI:** `/api/v1/openapi.json`
* **Администратор:** `ADMIN_EMAIL` / `ADMIN_PASSWORD` из `.env` (создаётся при первом запуске)
* **Тесты:** из корня проекта `python -m pytest server/tests -v`
* **Миграции вручную:** из корня проекта `alembic -c server/alembic.ini upgrade head`

### 2. Мобильный клиент (Godot Engine 4)

1. Запустите сервер (шаг 1). `server.py` сам запишет `client/server.cfg` с адресом компьютера в сети.
2. Откройте **Godot 4.5+**, импортируйте `client/project.godot`.
3. Запустите (F5) или экспортируйте APK: адрес сервера из `server.cfg` вшивается в сборку,
   вводить IP на телефоне не нужно. Телефон и компьютер должны быть в одной Wi-Fi сети.
4. Нестандартный адрес можно задать на экране входа в блоке «Настройки сервера».
   * Эмулятор Android: `http://10.0.2.2:8080`
   * USB-отладка без Wi-Fi: `adb reverse tcp:8080 tcp:8080` и адрес `http://127.0.0.1:8080`

## Выполнение всех 6 кейсов и критериев оценивания

### Кейс 1 — Финальный пользовательский интерфейс (UI/UX на Godot 4)
* **Полноценные экраны и сценарии:**
  * `AuthScreen.gd`: авторизация, регистрация с валидацией подтверждения пароля, запрос и подтверждение сброса пароля.
  * `SetupScreen.gd`: трехшаговый мастер первого запуска (выбор языка → выбор цели обучения → добавление рекомендованных словарей).
  * `HomeScreen.gd`: основной экран со вкладками:
    * `LearnTab.gd`: интерактивные тренировки (выбор перевода, карточки слов, аудирование, правописание), прогресс-бар вопросов, начисление очков и подсчет серии дней.
    * `LanguageTab.gd`: правила и грамматические особенности изучаемого языка, фонетический тренажер с озвучкой через системный TTS движка (`DisplayServer.tts_speak`).
    * `DictTab.gd`: каталог словарей с рекомендациями под выбранную цель обучения, просмотр слов словаря с серверным поиском, сортировкой и пагинацией.
    * `MyWordsTab.gd`: персональный словарь пользователя с **полным циклом CRUD**:
      * **Создание (Create):** форма добавления слова с автопереводом через внешний API MyMemory.
      * **Чтение (Read):** карточки слов со статусом «В изучении» / «Выучено», озвучкой и транскрипцией.
      * **Редактирование (Update):** форма редактирования слова, перевода, транскрипции и примера.
      * **Удаление (Delete):** удаление слова с диалогом подтверждения.
    * `ProfileTab.gd`: настройки профиля (имя, дневная цель слов, напоминания), детальная статистика (очки, серия, точность, история тренировок), кнопка смены языка/цели и **выход из аккаунта**.
    * `AdminTab.gd`: панель администратора (аналитика платформы, создание системных словарей, добавление слов, просмотр и удаление пользователей, переключение внешних интеграций).
* **Серверный поиск, фильтрация и сортировка:**
  * Поисковая строка передает параметр `search` в API (`GET /api/v1/my/words?search=...`).
  * Фильтр по статусу изучения: Все слова / Только изучаемые / Только выученные (`filter=learned` / `filter=unlearned`).
  * Сортировка: по порядку добавления, по алфавиту слова (А-Я, Я-А), по новизне (`sort_by=word`, `order=desc`).
* **(*) Загрузка данных частями (пагинация):**
  * В `MyWordsTab.gd` и `DictTab.gd` реализована постраничная загрузка данных (`limit` и `offset`).
  * Компонент `Ui.pagination_bar`: кнопки «← Назад», «Вперёд →», индикатор текущей страницы («Стр. X из Y (Всего: N)»).
* **Валидация до отправки запроса:**
  * Проверка обязательности полей, формата email, минимальной длины пароля (>= 6) и совпадения паролей до сетевого вызова.
* **Состояния интерфейса:**
  * Состояние загрузки (`BaseTab.loading()`), состояние успеха (зеленые уведомления `Ui.say(..., true)`), состояние ошибки сервера (понятные сообщения без падений).
* **Выход из аккаунта и безопасность сессий:**
  * Кнопка «Выйти из аккаунта» отправляет `POST /api/v1/logout` для отзыва токена, очищает локальное хранилище `user://linglearn.cfg` и возвращает на экран входа.
  * При получении `401 Unauthorized` (истечение срока JWT) срабатывает автоматический логаут с информационным уведомлением «Срок действия сессии истёк».

### Кейс 2 — REST API
* **Версионирование API:** все маршруты размещены под префиксом `/api/v1/` (для обратной совместимости также поддерживаются корневые алиасы).
* **Схемы Pydantic (v2):** строгое разделение входных (Request) и выходных (Response) схем в пакете `server/schemas/`.
* **Валидация входных данных:** проверка типов, допустимых диапазонов (`Field(ge=..., le=...)`), форматов email и длины строк.
* **Корректные HTTP статус-коды:**
  * `200 OK`: успешное получение данных, обновление профиля, вход, статистика.
  * `201 Created`: успешная регистрация (`POST /api/v1/register`), создание слова (`POST /api/v1/my/words`), создание словаря (`POST /api/v1/dictionaries`).
  * `204 No Content`: успешное удаление слова (`DELETE /api/v1/my/words/{id}`) или словаря.
  * `401 Unauthorized`: отсутствие или недействительность токена авторизации, неверный пароль.
  * `403 Forbidden`: попытка изменения/удаления чужого слова или доступ к эндпоинтам администратора обычным пользователем.
  * `404 Not Found`: ресурс не найден (слово, словарь, пользователь).
  * `409 Conflict`: повторная регистрация с уже существующим email.
  * `422 Unprocessable Entity`: невалидные входные данные по схеме Pydantic.
* **(*) Безопасная обработка исключений:** централизованные обработчики исключений в `main.py` скрывают traceback и внутренние SQL-ошибки от клиента, возвращая безопасные JSON-сообщения `{"detail": "..."}` и логируя детали в системный лог.
* **Документация:** автоматически генерируемая OpenAPI/Swagger документация на `/docs` и `/redoc`.

### Кейс 3 — Проектирование и миграции БД
Основная СУБД — **PostgreSQL** (docker-compose). Спроектирована реляционная модель из **9 таблиц** с соблюдением 3NF:
1. `users` — пользователи (PK, UNIQUE email, NOT NULL, CHECK constraints на streak >= 0, points >= 0, daily_goal).
2. `languages` — языки обучения (PK code, CHECK на niche IN (0, 1)).
3. `language_features` — грамматические и фонетические правила (FK -> `languages.code` ON DELETE CASCADE).
4. `dictionaries` — словари (PK, FK -> `languages.code` ON DELETE RESTRICT, FK -> `users.id` ON DELETE SET NULL, CHECK на is_public).
5. `words` — слова (PK, FK -> `dictionaries.id` ON DELETE CASCADE, NOT NULL).
6. `user_dictionaries` — **промежуточная таблица для связи N:M** между `users` и `dictionaries` (составной PK `(user_id, dict_id)`, FK ON DELETE CASCADE).
7. `user_word_progress` — прогресс изучения слов (FK -> `users.id`, FK -> `words.id`, UNIQUE constraint `(user_id, word_id)`, CHECK constraints).
8. `test_results` — результаты тестирования (FK -> `users.id` ON DELETE CASCADE, FK -> `dictionaries.id` ON DELETE SET NULL, CHECK constraint `total >= score`).
9. `revoked_tokens` — черный список отозванных JWT токенов (PK, UNIQUE jti, index).

* **Связи:**
  * **1:N:** `languages` → `dictionaries`, `dictionaries` → `words`, `users` → `user_word_progress`, `users` → `test_results`, `languages` → `language_features`.
  * **N:M:** `users` ↔ `dictionaries` через промежуточную таблицу `user_dictionaries`.
* **Обоснование правил удаления (ON DELETE):**
  * `CASCADE`: удаление словаря автоматически удаляет его слова; удаление пользователя удаляет его личный прогресс и результаты тестов, так как они не имеют смысла без владельца.
  * `SET NULL`: при удалении автора публичного словаря авторство сбрасывается в `NULL`, но сам словарь и прогресс других студентов сохраняются.
  * `RESTRICT`: запрет удаления языка, если к нему привязаны словари платформы.
* **Нормализация (3NF):** данные о языках вынесены в отдельную сущность, слова не дублируют метаданные словарей, связь пользователя со словарями вынесена в ассоциативную таблицу.
* **Обоснованные индексы:** `ix_users_email` (быстрый поиск при входе), `ix_dictionaries_lang_goal` (фильтрация по языку и цели), `ix_words_dict_id` (выборка слов словаря), `ix_user_word_progress_user_id`, `ix_revoked_tokens_jti`.
* **Миграции Alembic:**
  * `e47af060ab93_initial_schema.py`: начальная миграция создания всех таблиц, связей, ограничений и индексов.
  * `7f8a9b0c1d2e_add_indexes_and_notes.py`: последующая миграция изменения схемы (добавление поля `notes`, составных индексов `ix_user_word_progress_user_learned` и `ix_test_results_user_created`).
  * `b3c4d5e6f7a8_add_reset_code_expiry.py`: срок действия кода восстановления пароля (`users.reset_code_expires_at`).
* **(*) Развёртывание на пустой БД исключительно миграциями:** при старте сервер выполняет `alembic upgrade head`; `create_all` в коде приложения не используется. Проверяется тестом `tests/test_migrations.py`.
* **(*) Ограничения целостности на уровне самой БД:** применены `CHECK`, `UNIQUE`, `NOT NULL` и `FOREIGN KEY` во всех моделях.

### Кейс 4 — ORM (SQLAlchemy 2.0)
* Декларативные модели на базе `DeclarativeBase`, `Mapped` и `mapped_column` в `server/models/`.
* Описание связей через `ForeignKey` и `relationship(..., back_populates=...)`.
* Современный синтаксис сессий и селекций `select(Model).where(...)`.
* Полноценный CRUD через ORM для слов, словарей, пользователей и прогресса.
* **(*) Запросы с условиями, сортировкой, limit и offset:**
  * Метод `WordRepository.list_by_dictionary` и `ProgressRepository.list_my_words` динамически применяют фильтры `ilike`, сопоставление безопасных атрибутов модели для `order_by` (`desc()` / `asc()`), `limit()` и `offset()`.
* **(*) Управление транзакциями (commit и rollback):**
  * Все многошаговые операции (сохранение результата теста + обновление карточек слов + начисление очков + обновление серии дней) выполняются атомарно внутри блока `try ... except` с гарантированным `rollback()` при ошибке.
* **Предотвращение проблемы N+1:**
  * Использование стратегий загрузки `selectinload(Dictionary.words)` и `joinedload` при выборке словарей и прогресса.
* **Разделение слоев:** ORM-модели строго изолированы от Pydantic-схем.
* **(*) Безопасность SQL:** полное отсутствие строковой конкатенации пользовательского ввода; все запросы параметризованы через ORM.

### Дополнительный кейс 6 — Безопасность
* **Регистрация и валидация:** проверка формата email по регулярному выражению, длины имени (>= 2), пароля (>= 6) и подтверждения пароля.
* **Защита от дубликатов:** проверка существования пользователя в сервисе + ограничение `UNIQUE` на уровне БД.
* **Хеширование паролей:** использование криптографической библиотеки `bcrypt` (12 раундов солирования).
* **JWT Токены:** после входа генерируется криптографически подписанный токен (`HS256`) со сроком жизни (`exp`), идентификатором пользователя (`sub`) и уникальным UUID токена (`jti`).
* **(*) Заголовок авторизации:** токен передается строго в заголовке `Authorization: Bearer <token>`.
* **Черный список отозванных токенов:** при логауте токен заносится в таблицу `revoked_tokens` и мгновенно перестает приниматься сервером.
* **Защита личных данных:** операции изменения и удаления записей проверяют принадлежность слова/словаря текущему пользователю. При попытке изменить чужую запись возвращается `403 Forbidden`.
* **Безопасные ответы API:** пароли, хеши паролей, секретные ключи исключены из всех Pydantic схем ответов.
* **Секреты:** `SECRET_KEY` берётся только из окружения (значения по умолчанию в коде нет, сервер не стартует без ключа >= 32 символов); `.env` в `.gitignore`, шаблоны `.env.example` содержат пустые/фиктивные значения.
* **Восстановление пароля:** код не возвращается в ответе API (только в серверном журнале как «SMTP-заглушка»; для отладки есть флаг `DEV_EXPOSE_RESET_CODE`), живёт `RESET_CODE_TTL_MINUTES` минут, одноразовый; ответ одинаков для существующих и несуществующих email.
* **Сокрытие исключений сервера:** внутренние ошибки логируются на сервере с полным стек-трейсом, а пользователю отдается нейтральный JSON `{"detail": "Внутренняя ошибка сервера"}`.
